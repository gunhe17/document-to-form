# 완전성 감사 랩 (recall audit)

**질문:** 위치 파악 *전단계*에서, 위치가 필요한 **모든 요소를 빠짐없이 가져오는가?**
(좌표 정확도가 아니라 **누락 없이 다 담았는가** = recall)

## 왜 이 지표인가
CV는 요소가 **목록에 있어야** 좌표를 잡는다. 전단계가 요소를 놓치면 CV는 영영 못 본다.
그래서 진짜 실패 모드는 bbox 오차가 아니라 **누락**. 이 랩은 오직 누락만 본다.

## 구성
```
groundtruth/*.json   폼별 정답 요소 목록 (사람이 채우는 모든 칸). 검토·수정 가능.
cache/*.json         추출법별 결과 캐시 (LLM 재호출 방지). 지우면 재생성.
run_audit.py         정답 대비 4가지 추출법 매칭 → recall·누락 → report.html
report.html          결과 (폼 탭 · 방식별 recall 바 · 요소×방식 매트릭스)
```

## 비교하는 4가지 추출법
| 방식 | 입력 | 성격 |
|---|---|---|
| CV 트리거 | PNG | 결정론 규칙(단위·콜론·□) — 트리거 있어야 발화 |
| HWPX 텍스트 | HWPX 셀 텍스트 | LLM이 구조·의미로 예측 |
| 셀 ID | HWPX 셀(ID) | LLM이 입력셀 ID 지목 |
| 멀티모달 | HWPX+MD+PNG | 비전 LLM 한 번에 |

## 실행
```
python3 run_audit.py     # 캐시 없으면 LLM 호출, 있으면 재사용
rm cache/*.json          # 다시 뽑고 싶을 때
```

## 결과 요약 (2026-07, consent 타입 추가 후)
| 방식 | 서식2호 | 서식15호 | 서식4-1호 |
|---|---|---|---|
| CV 트리거 | 71% | 95% | 90% |
| HWPX 텍스트 | 89% | 100% | 100% |
| 셀 ID | 86% | 95% | 95% |
| 멀티모달 | 86% | 95% | 95% |

**결론:** 텍스트·셀·비전 기반은 트리거 CV를 일관되게 앞선다(특히 복잡한 서식2).

### 산문형 동의 블록 (해결)
초기 누락 원인 = **프롬프트 type enum에 `consent`가 없어 LLM이 출력할 수 없었음** (인식 실패 아님).
few-shot 불필요 — enum에 `consent` + 한 줄 설명만으로 3개 LLM 방식 모두 동의 필드 검출.

### 알려진 caveat
- temp=1.0 → 재실행마다 ±몇 개 변동(119신고시간·칼라사진 등). 안정 측정하려면 temp↓ 또는 N회 평균.
- GT는 best-effort. (서식2 동의는 폼에 1개인데 초기 GT가 2개로 과분할 → 정정함.)
