image-to-form 파이프라인

정부 서식(HWPX+스캔) → FormSchema 계약. 원칙: 도구=좌표 · LLM=의미

결정론(도구/CV) · $0 · 픽셀정확 LLM(의미) · ~1~2¢/폼 하드코딩(사전·CV상수) 일반화된 규칙
📥 입력   HWPX(표 topology)  +  스캔 이미지(PNG)
│
🔵 결정론 층 — 좌표 검출 (LLM 없음)
1. HWPX 파싱셀 topology(addr/span/sz) → solve_grid → 정규화 rect. 캡션행 제거, 다중표는 region별 분리일반화
2. 격자 정렬이미지 괘선 검출 → DP-align → HWPX 경계에 픽셀 스냅. 스캔 drift 흡수CV상수 <110·50px
3. 입력 검출 규칙체크박스(엣지□) · 인라인슬롯(단위+공백갭) · 콜론(명:) · 빈괄호( ) · 선택지(남/여, cs<3) · 서명마커사전 UNITS·선택쌍
elements[ ]   (kind, raw_label, rect[x,y,w,h]) — 절대 픽셀
🟣 LLM 층 — 의미 생성 (Gemini 3.1 · reasoning=low)
4. fields 생성거친 라벨 정제(과전문의의사명→전문의 의사명) · 타입 판정 · ids 병합(체크박스 옵션·날짜 년월일) · 그룹 추론사전 없이 문맥 판단
│
🟢 정합화 글루 — 결정론이 LLM을 검증·교정
5. 요소=진실요소가 옵션(=선택지) 들면 그게 진실 → LLM 타입 오분류 교정 (am/pm을 time→radio)일반화
│
🟠 FormSchema 계약 — imomtae 3평면 + 관계
pages배경 이미지·크기
fields의미 키 → 타입·라벨·옵션·그룹 [LLM]
elements정규화 rect + widget + field_refs [도구]
constraints크로스필드 관계 [LLM]
✓ pydantic 검증: option∈field.options · field_refs 무결성 · rect 0..1
│
📤 출력   FormTemplate.schema (JSONB) — imomtae에 그대로 삽입

🔵 도구가 하는 일 vs 🟣 LLM이 하는 일

도구/CV
박스 위치, 괘선정렬, 체크박스/슬롯 검출 — 좌표는 LLM이 안 건드림
LLM
라벨 정제, 타입 판정, 병합, 그룹 — 애매한 의미 판단
글루
요소 사실로 LLM 오분류 교정 (양방향 검증)
