# 비용

모델: `google/gemini-3.1-pro-preview` (OpenRouter), `reasoning={"effort":"low"}`, `temperature=1.0`.
숫자는 OpenRouter API 응답의 `usage.cost` 실측값(추정 아님). 요율: 입력 $2/M · 출력 $12/M.

## 페이지당 비용 — 요소 수에 비례

`pipeline.build`는 페이지당 **그라운딩 1콜**뿐이다(중첩표 크롭 없음). 입력토큰은 이미지+프롬프트로 거의 고정(~1877)이고, **출력토큰이 비용을 지배**한다 — 출력은 요소마다 좌표(box)+타입을 뱉고 거기에 low-effort reasoning이 더해져 요소 수에 비례해 늘어난다.

| 문서 | atom | 요소 | 입력토큰 | 출력토큰 | 실측 비용 |
|---|---|---|---|---|---|
| 서식15호 | 37 | 56 | 1877 | 3551 | **$0.0464** |
| 서식2호 | 50 | 60 | 1877 | 3521 | **$0.0460** |
| booklet p12(촘촘) | 141 | 129 | 1878 | 7236 | **$0.0906** |

입력토큰이 atom 수와 무관하게 일정한 건, SoM 번호가 이미지 위 픽셀일 뿐 토큰이 아니고 이미지 자체 크기가 비용을 지배하기 때문. 요소가 2.3배(56→129) 늘면 출력토큰도 ~2배(3551→7236), 비용도 ~2배($0.046→$0.091).

## 어림 공식

```
페이지 비용 ≈ $0.012(고정) + 요소수 × $0.0006
```

**근거**: 출력토큰 ≈ 720 + 50 × 요소수 (reasoning 오버헤드 ~720 + 요소당 ~50). 입력 1877 × $2/M ≈ $0.0038, 고정 출력분 720 × $12/M ≈ $0.0086 → 합쳐 고정 ~$0.012, 요소당 50 × $12/M ≈ $0.0006. 검증: 요소 56 → $0.046, 요소 129 → $0.090 (실측과 일치).

## image-to-md 대비

같은 모델·같은 페이지라도 image-to-form이 더 비싸다: [[image-to-md/price.md]] 본문 콜은 출력 ~1145토큰($0.016)인데, 그라운딩은 요소마다 box 4좌표를 뱉어 출력 3500~7200토큰으로 3~6배. **전사(md)는 "읽은 것"만, 그라운딩(form)은 "요소마다 위치"까지 내보내므로 출력이 크고 그만큼 비싸다.** 대신 콜은 페이지당 1콜로 최소(중첩표 크롭 없음).

## 규모 감

13문서(대부분 표 1페이지, 요소 40~130)를 한 번 처리하면 대략 **$0.6~0.9**. 캐시(`cache_path`)를 쓰면 재실행은 무료 — 반복 검증(`_verify/render.py`)은 첫 1회만 과금.
